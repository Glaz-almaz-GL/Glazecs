## 2026-09-25 — Папка установки только для чтения

Проблема:
Программа, установленная в `C:\Program Files (x86)\Glazecs`, не запускалась. Без прав администратора окно оставалось пустым, от администратора появлялась ошибка «Не удалось создать каталог данных» с путём `Glazecs.exe.WebView2\EBWebView`.

Что произошло:
WebView2 по умолчанию создаёт каталог данных рядом с exe. Обычный пользователь не может писать в `Program Files`, поэтому WebView2 не стартовал. Исправление (`WEBVIEW2_USER_DATA_FOLDER` → `%LOCALAPPDATA%\Glazecs\WebView2Cache`) уже было в коде, но установленная копия была собрана раньше него. Поэтому сначала стоило проверить, какая версия реально запущена, и только потом искать ошибку в коде.

Вывод:
Всё, что программа пишет во время работы (кэш, настройки, логи), должно лежать в `LocalAppData`, а не рядом с exe. Папка установки — только для чтения. Перед разбором бага в коде сверяй дату сборки установленной копии с датой исправления.

## 2026-09-25 — Версии пакетов в одном месте

Проблема:
Версии NuGet-пакетов были прописаны в 10 csproj и разошлись (`Microsoft.Maui.Controls` 10.0.80 и `$(MauiVersion)`, `CommunityToolkit.Maui` 14.2.0 и 14.2.2).

Вывод:
Central Package Management (`Directory.Packages.props`) хранит версию каждого пакета в одном месте. Обновление пакета — одна правка, а версии одного пакета не расходятся между проектами. Аналогично номер версии приложения задаётся одним свойством `<Version>`, остальное (`AssemblyVersion`, `FileVersion`, `ApplicationDisplayVersion`) берётся из него. Свойства MSBuild вычисляются сверху вниз, поэтому `$(Version)` должен быть объявлен раньше, чем используется.
